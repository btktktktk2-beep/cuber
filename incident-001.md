# Отчёт об инциденте №001: неудачные попытки входа в чужую учётную запись

**Дата:** 09.11.2026
**Система:** учебная ВМ xubunty (Xubuntu)
**Источник данных:** системный журнал (`journalctl`)
**Учебный сценарий:** попытки смоделированы в собственной лаборатории.

## Описание
09.11.2026 в период с 11:11:55 по 11:16:21 пользователь `vboxuser` (uid=1000) с терминала `/dev/pts/0` дважды пытался получить доступ к учётной записи пользователя `tester` с помощью утилиты `su`. Обе попытки завершились отказом в доступе (`FAILED SU`).

## Хронология
| Время | Источник | Событие |
| --- | --- | --- |
| 11:11:55 | `su[8513]` | `FAILED SU (to tester) vboxuser on pts/0` |
| 11:16:19 | `unix_chkpwd[8674]` | `password check failed for user (tester)` |
| 11:16:19 | `su[8672]` | `pam_unix(su-l:auth): authentication failure; logname=vboxuser uid=1000 tty=/dev/pts/0 user=tester` |
| 11:16:21 | `su[8672]` | `FAILED SU (to tester) vboxuser on pts/0` |

## Анализ
- Тип события: попытка доступа к чужой учётной записи (не повышение привилегий: у `tester` нет прав выше, чем у `vboxuser`).
- Попытка в 11:16 подтверждена записями PAM (`authentication failure`) и `unix_chkpwd` (`password check failed`).
- По попытке в 11:11 в выборке зафиксирован только итоговый отказ (`FAILED SU`); подробные записи требуют проверки за более широкий период.
- Попытки локальные (терминал `pts/0`), удалённого адреса (`rhost`) нет.
- Доступ к учётной записи `tester` получен не был.

## Рекомендации
1. Выяснить у пользователя `vboxuser` причину попыток входа.
2. При повторении настроить блокировку учётной записи после нескольких неудачных попыток (`pam_faillock`, `fail2ban`).
3. Настроить оповещение о событиях `FAILED SU` и `authentication failure`.

## Команды для проверки
```
journalctl --since "2026-11-09 11:00" --until "2026-11-09 11:30" | grep -i fail
journalctl _COMM=su --since "2026-11-09"
```
