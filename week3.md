# Неделя 3. Процессы, службы, журналы, пакеты, скрипты

## Процессы
| Команда | Что делает |
| --- | --- |
| `ps aux` | список всех процессов (первая строка — заголовок) |
| `ps -p 1` | процесс с PID 1 — это `systemd`, он запускает все остальные |
| `top` | процессы в реальном времени (`c` — полная команда, `q` — выход) |
| `pgrep имя` | найти PID по имени |
| `kill PID` / `kill -9 PID` | завершить процесс / убить принудительно |
| `команда &` | запустить в фоне |
| `$(команда)` | подставить результат одной команды в другую |

Принцип наименьших привилегий: терминал и браузер работают под обычным пользователем, root берётся через `sudo` только когда нужно.

## Службы
| Команда | Что делает |
| --- | --- |
| `systemctl status имя` | состояние службы (`Active:` и `Loaded:`) |
| `sudo systemctl stop/start имя` | остановить / запустить сейчас |
| `sudo systemctl disable/enable имя` | убрать из автозапуска / добавить |
| `sudo systemctl disable --now имя` | остановить и убрать из автозапуска сразу |
| `systemctl list-units --type=service --state=running` | работающие службы |

- Базовая линия моей системы: 24 работающие службы. Новая незнакомая служба — повод проверить.
- `cups` будят `cups.socket` и `cups.path` (строка `TriggeredBy`): отключать нужно все три.
- Каждая лишняя служба — лишняя точка для атаки (hardening).

## Журналы
| Команда | Что делает |
| --- | --- |
| `journalctl -u имя` | записи одной службы |
| `journalctl -n 20` | последние 20 записей |
| `journalctl --since "5 min ago"` | записи за период |
| `journalctl -p err` | только ошибки |
| `journalctl ... \| grep -i fail` | неудачные попытки (`-i` — без учёта регистра) |

Строка журнала: дата и время → имя компьютера → кто записал (`su[8672]`) → что произошло.
- `sudo` пишет: кто запустил, от чьего имени (`USER=root`), какую команду (`COMMAND=`).
- `pam_unix` — модуль проверки паролей, сообщает об `authentication failure`.
- Первый отчёт об инциденте: [incident-001.md](incident-001.md).

## Пакеты
| Команда | Что делает |
| --- | --- |
| `apt show имя` | описание пакета |
| `sudo apt install имя -y` | установить |
| `sudo apt remove имя -y` | удалить |
| `which имя` | где лежит программа |

Программы ставить только из официальных репозиториев: пакеты подписаны, `apt` проверяет подпись. Источники — `/etc/apt/sources.list.d/ubuntu.sources`, обновления безопасности идут с `security.ubuntu.com`.

## Скрипты
- Первый скрипт: [backup.sh](backup.sh) — архив папки с датой в имени.
- `#!/bin/bash` — каким интерпретатором запускать.
- Переменная создаётся без `$` (`DEST=~/backups`), используется с `$` (`$DEST`).
- Переменные живут только внутри скрипта: в терминале они пустые.
- `nano файл` — редактор: Ctrl + O сохранить, Ctrl + X выйти.
- `tar -czf архив папка` — упаковать, `tar -tzf архив` — посмотреть содержимое.

## Выводы недели
- Результат всегда проверять: «нет ошибки» не значит «сработало» (`cups` остался `enabled`).
- Пустая переменная может сломать команду: путь превращается в `/lesson1_.tar.gz`.
- **Права файла не защищают его копии.** Архив с правами `rw-rw-r--` позволил другому пользователю распаковать `secret.txt` и стать владельцем копии. Бэкапы с секретами — только `chmod 600`, лучше с шифрованием.
